# 記憶共享方法（Codex ⇄ Claude）— 可攜，換資料夾可重建

> 目的：讓 **Claude Code** 與 **Codex** 在同一個專案資料夾共用同一套「記憶／踩雷／交接」知識，
> 不靠任何一方私有的自動記憶機制，全部落在 repo 內的純 markdown，可進 git、可手動讀。
> 最後更新：2026-06-04。

---

## 1. 為什麼要這樣做（背景）

兩個 AI 的「自動記憶」天生不互通：

| | Claude Code | Codex |
|---|---|---|
| 專案規則檔 | repo 根 `CLAUDE.md` | repo 根 `AGENTS.md` |
| 全域規則檔 | `~/.claude/CLAUDE.md` | `~/.codex/AGENTS.md` |
| 自動記憶 | `~/.claude/projects/<proj>/memory/*.md` + `MEMORY.md`（自動 recall） | `~/.codex/memories/` + sqlite（內部） |

兩邊唯一**天然共享**的，是 repo 根那兩個檔（因為兩個 agent 在同一資料夾各自會自動讀）。
所以策略不是「同步兩套私有記憶」，而是 **建一份共享檔、兩邊都被指示去讀**。

---

## 2. 架構：單一真相來源（single source of truth）

```
<專案根>\
├── CLAUDE.md          ← Claude 自動讀；內容 == AGENTS.md
├── AGENTS.md          ← Codex 自動讀；內容 == CLAUDE.md
└── <共享區資料夾>\     ← 本專案用 AI_交接\（在專案根 D:\FLAC_AI\AI_交接\）
    ├── HANDOFF.md          進度交接（冷讀現況）
    ├── GOTCHAS.md          踩雷與解法（遇到新雷追加）
    ├── CHANGELOG.md        CLAUDE/AGENTS 變更記錄
    └── 記憶共享方法.md      本檔（機制說明 + 重建步驟）
```

規則三條：
1. **記憶集中在 `GOTCHAS.md`**：`CLAUDE.md`/`AGENTS.md` 保持精簡，只放專案規則 + 一個指標（遇到問題去查 GOTCHAS.md）。不要把踩雷細節塞進 CLAUDE.md，以免越改越亂。
2. **`CLAUDE.md` 與 `AGENTS.md` 不必即時同步**：內容相近即可，**每 2~3 天對齊一次**（`Copy-Item CLAUDE.md AGENTS.md`）。
3. **HANDOFF.md 是需要時才讀**，不是每次對話都開；`GOTCHAS.md` 才是「遇到問題先查」的對象。

> Claude 端取捨：搬到 repo 檔會失去 Claude 自動記憶的「相關性 recall」（不用叫就浮現）。
> 折衷：canonical 內容放共享區，Claude 的 `MEMORY.md` 只留**一行指標**指向共享區，兩邊都受惠又不重複。

---

## 3. 每個 agent 的工作守則（已寫進 CLAUDE.md/AGENTS.md banner）

- **遇到問題先查** `GOTCHAS.md`（別重犯舊雷）。
- **踩到新雷／找到解法** → 追加到 `GOTCHAS.md`（用該檔文末模板）。
- **需要交接現況時才讀／更新** `HANDOFF.md`（非每次對話）。
- **改了 `CLAUDE.md`/`AGENTS.md`** → 在 `CHANGELOG.md` 追加一行；兩檔不必當下同步，**每 2~3 天 `Copy-Item` 對齊一次**即可。

---

## 4. 換資料夾時如何重建（複製即用的步驟）

設新專案根為 `<NEW>`，共享區資料夾自取（例 `<NEW>\_shared` 或 `<NEW>\AI_交接`）。

1. **建共享區**：把本資料夾的 `GOTCHAS.md` / `CHANGELOG.md` / `記憶共享方法.md` 複製過去（FLAC3D 類踩雷可直接沿用）；視需要新建 `HANDOFF.md`。
2. **建/改 `CLAUDE.md`**：頂部加入下面 §5 的 banner（把共享區路徑換成新位置）。
3. **產出 `AGENTS.md`**：`Copy-Item <NEW>\CLAUDE.md <NEW>\AGENTS.md`（PowerShell）。之後兩檔每 2~3 天對齊一次即可，不必即時同步。
4. **（Claude 才有）留指標**：在 `~/.claude/projects/<新proj>/memory/MEMORY.md` 加一行
   `- [跨 AI 共享區] 見 <NEW>\<共享區>\（GOTCHAS/HANDOFF/CHANGELOG，Claude/Codex 共用）`。
5. **驗證一致**：`diff <NEW>\CLAUDE.md <NEW>\AGENTS.md` 應無差異。

> 對齊小技巧：固定只編輯 `CLAUDE.md`，每 2~3 天跑一次 `Copy-Item CLAUDE.md AGENTS.md` 讓 Codex 端跟上。
> （亦可改用 symlink：`New-Item -ItemType SymbolicLink -Path AGENTS.md -Target CLAUDE.md`，但 git/部分工具對 symlink 支援不一，預設用複製較穩。）

---

## 5. Banner 範本（貼到 `CLAUDE.md`/`AGENTS.md` 頂部，換路徑即可）

```markdown
## 🔗 跨 AI 共享記憶區（Codex / Claude 共用）

共享區位置：<共享區資料夾路徑>
- `GOTCHAS.md`     — 踩雷與解法。遇到問題先查這裡；找到新解法請追加。
- `HANDOFF.md`     — 進度交接，需要時再讀（非每次對話）。
- `CHANGELOG.md`、`記憶共享方法.md` — 變更記錄與本機制說明。

註：CLAUDE.md 與 AGENTS.md 內容相近即可，不必即時同步，每 2~3 天對齊一次。
```

---

## 6. 一句話總結
**把知識寫進 repo 內共享 markdown，`CLAUDE.md`==`AGENTS.md` 當入口指標，兩個 AI 各自自動讀入口、被指示去讀共享區。** 換資料夾照 §4 重建即可。
